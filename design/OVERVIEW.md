# Boardes — 概要・UIの意図・画像だけでは分からない挙動

このファイルはビジュアルデザインの検討用に、アプリの背景・各画面の意図・スクリーンショットには
写らない挙動をまとめたもの。`screens/*.png` (9枚) と併せて参照してください。実装は Qt6 Widgets /
C++23 のデスクトップアプリで、Web コンポーネントではないため、ここでの提案はあくまで
「見た目・レイアウト・情報密度の方向性」であり、実装への反映は色 (QSS)・レイアウト (.ui ファイル)・
アイコン (SVG) という限られた形で人力で移植する前提です。

## 1. 全体概要

**Boardes** は、ユニバーサル基板 (蛇の目基板・ベロボード) の部品配置・配線を設計するための CAD 風
デスクトップアプリ。既存の日本語フリーソフト「PasS」(Parts Arrange Support System) と互換の
使い勝手を目指しつつ、PasS 自体には依存しない独立実装。想定ユーザーは電子工作の趣味人で、
実際に手ではんだ付けする物理基板の部品配置・配線経路を、組み立て前に画面上で検討・記録するために使う。

設計上の重要な前提:
- **1 ピクセル = 1 単位 = 0.254mm**。部品のアートワークは常にラスタ画像で、ピクセルとモデル座標が
  1:1 対応する (ズームで滲まない、というより「そもそも縮尺換算が要らない」)。
- **基板はパラメトリックなデータ**(列数・行数・ピッチ・穴形状など) として持つが、**背景画像を
  添付して見た目のすべてをその画像に委ねることもできる**(後述)。どちらの基板も同じ当たり判定・
  スナップ・電気的ネット計算のロジックで動く。
- **表面/裏面を横に並べた2ビュー構成**。裏面ビューは基板を透かして裏から見た状態を水平反転で
  表示する。配線は表裏で色分けされ (表=青、裏=オレンジ)、この色分けは画面全体で一貫させている
  (ツールバーのボタン名からハイライト、ネット表示まですべて同じ色分け)。
- **ライブラリシステム**: 部品・基板は「ライブラリ」という単位でまとめて管理し、各ライブラリは
  ライセンス・再配布可否・編集可否を持つ。読み込み専用のライブラリは「複製」することでのみ
  編集可能になる (詳細は §3 のライブラリ関連ダイアログを参照)。

## 2. 画面ごとの意図

### メインウィンドウ (`main-window-drc.png` / `main-window-stats.png`)

4カラム構成: **部品セレクタ(左) / 表面ビュー / 裏面ビュー / 解析パネル(右)**、上部にメニュー・
2段のツールバー、下部にステータスバー。

- 表示系ツールバー(1段目): ズーム操作 → 表裏レイアウト切替 → **レイヤ表示トグル群**(表面配線/
  裏面配線/被覆(表)/被覆(裏)/外形線/アウトライン/ピン番号/番号・値)。トグルは押下状態を持つ
  チップ風ボタンの列で、現在は全部同じ見た目の QToolButton が並んでいるだけなので、
  グループ化・優先度づけの余地が大きい。
- ツール系ツールバー(2段目): **排他選択の6ボタン**(選択/配線×4種/下書き) + 配線スナップの
  ドロップダウン(フル・ハーフ・フリー)。この6ボタンは「今アクティブな操作モード」を表すので、
  排他グループであることが視覚的にもっと分かりやすくなると良い。
- 部品セレクタ: ライブラリ別/カテゴリ別/全部品の3モード切替 + 検索 + アイコングリッド。
  部品数は数十〜数百件になりうるので、グリッドの情報密度(サムネイルサイズ・ラベルの有無)は
  重要な検討ポイント。
- 解析パネル: **DRC タブと統計タブ**を1つのドックにタブでまとめている。DRC は重要度(エラー/警告)
  付きの一覧、統計は数値サマリ + BOM 表。この2つは性質が違う(前者は「直す」ためのもの、後者は
  「確認する」ためのもの)ので、同じタブUIで良いか含めて検討の余地がある。

### About (`about.png`)

サードパーティライセンス表示のみの簡素なダイアログ。デザイン上の優先度は低い。

### 基板エディタ (`board-editor.png`)

新規/既存の基板を作成・編集するダイアログ。上から: ID/名前 → 格子パラメータ(列数・行数・
ピッチ・原点) → パッド形状・パッド直径・穴直径・銅箔パターン → 両面基板トグル → 基板色
(基板・パッド・銅箔の3色スウォッチ) → **表面/裏面の背景画像**(サムネイル + 開く/クリア) →
導出済みサイズの確認バナー。

このスクリーンショットでは実際の PasS 基板データ(ICB-504)を背景画像として添付した状態を
示している。フォームの後半(背景画像セクション)は今回追加したばかりの機能で、既存の格子
パラメータ群と視覚的に同じ密度で並んでいるが、**性質としては「格子パラメータを手で決める」か
「画像に丸ごと任せる」かの二者択一に近い**(背景画像がある場合、基板サイズは自動的に画像サイズに
従い、格子パラメータの意味合いが「画像の上にどう穴を重ねるか」に変わる)。この二者択一の
関係性をレイアウトで表現できると良い。

### 部品エディタ (`part-editor.png`)

ラスタ画像を読み込み、キャンバス上をクリックしてピンを打っていく画面。左側にキャンバス
(クリックでピン追加、右クリックで削除) + クロマキー設定(透過色・スポイト) + 新規ピンの
ドリル径・番号なしモード、右側にメタデータフォーム + ピン一覧テーブル(ドリル径のみ
インライン編集可)。

キャンバスは小さい部品画像を等倍以上に拡大表示しており(最近傍拡大、ドット感を維持)、
ピンは赤(番号あり)/青(番号なし=ドリル穴)の丸で重ねて描く。この画面は「精密な位置合わせ作業」
なので、キャンバスの視認性(グリッド線の有無、ピンの当たり判定の大きさの可視化など)が
使い勝手に直結する。

### ライブラリ管理 (`library-manager.png`)

左にライブラリ一覧(読み込み専用のものは灰色表示 + 施錠アイコン相当の視覚区別)、
その下に選択中ライブラリの詳細(名前・ID・バージョン・作者・ライセンス・編集可否・
再配布可否・部品数など)、右に操作ボタン列(インストール/複製/エクスポート/
メタデータ編集/削除)。ボタンは対象ライブラリの状態によって有効/無効が変わる
(例: マイライブラリは削除不可、読み込み専用ライブラリはメタデータ編集不可)。

### ライブラリのメタデータを編集 (`library-metadata.png`)

名前・バージョン・作者・作者URL・ホームページ・説明・ライセンス選択のフォーム。
ライセンス選択に応じて「再配布可否」のプレビュー文言が自動更新される(グレーアウトした
説明テキストとして表示)。**編集可能なライブラリ(マイライブラリ、または複製したもの)にしか
出せない画面**。

### ライブラリを複製 (`duplicate-library.png`)

読み込み専用ライブラリを編集可能にする唯一の手段。ID/名前/作者/バージョンを**複製元と
異なる値に変更することを強制**するバリデーションがある(冒頭にその指示文を表示)。
ライセンス欄は複製元のライセンスの性質によって選択肢が制限されることがある
(コピーレフト系なら同一ライセンスに固定、NC系ならNC系のみ、など)。この「なぜ選べないのか」
という制約の理由が、現状はライセンス欄の下の小さな注記でしか説明されていない。

### 画像エクスポート設定 (`export-image-options.png`)

対象(表面/裏面/表裏並べる)・拡大率・背景透過の3項目だけの小さなダイアログ。
デザイン上の優先度は低い。

## 3. 画像からは分からない挙動

スクリーンショットは静止画なので、以下のような**インタラクション・状態遷移・自動化された
振る舞い**は画像だけでは伝わらない。ビジュアルデザインを検討する際にも、これらが成立する
余地を残してほしい。

### 選択・移動・編集全般
- 部品/配線はドラッグで移動でき、常にグリッドにスナップする(部品は常にフルピッチ、配線は
  ツールバーの粒度設定に従う)。
- すべての編集操作(配置・移動・回転・表裏反転・配線追加・削除など)は `Undo/Redo` 対応。
  複数操作をまとめて1回の Undo で戻せる「マクロ化」も一部で使っている(例: 複数選択したものを
  まとめて移動)。
- 右クリックで文脈メニュー: 部品なら「回転/表裏切替/コピー/削除」、空白なら(クリップボードに
  何かあれば)「貼り付け」。
- キーボード操作: `Delete`/`Backspace` で削除、`R` で回転、`F` で表裏反転、`Ctrl+C`/`Ctrl+V` で
  コピー&オフセット貼り付け、矢印キーで1グリッド分の微調整。

### 配線とネット(電気的接続)
- **配線は直交または45度のみ**(PasS と同じ制約)。ツール使用中、頂点は8方向にスナップする。
- 配線にマウスを重ねる(クリックしなくてよい)と、**同じ電気的ネットに属する配線がすべて
  ハイライトされる**(シアン色のハロー)。これは「マウスを動かした瞬間に再計算」ではなく
  「ホバー対象の配線が変わった時だけ」再計算するので体感は軽い。
- ネット計算は「番号付きピンの足は表裏を貫通する」「片面基板では表面配線が裏面と自動的に
  繋がる(ジャンパはんだ付けの表現)」「裸線は経路上のどの点で触れても導通、被覆線は
  端点でしか繋がらない」といった、はんだ付けの物理的な現実を反映したルールで動く。

### DRC(デザインルールチェック)パネル
- **編集するたびに自動で再検査**が走る(手動の「再検査」ボタンは念のための保険で、通常は
  押さなくても最新の状態になっている)。
- 一覧の行を**クリックすると、該当箇所へ表示がジャンプし、関連する部品/配線が選択状態になる**。
  「見て終わり」ではなく「そこへ連れて行かれる」体験。
- 検出するのは7種類: 未接続ピン(警告)/同じ穴の共有(エラー)/部品アウトラインの重なり(警告、
  ICソケット+IC は正常なので警告止まり)/基板外形の外(エラー)/裸線同士の格子点外交差(エラー、
  ショートの可能性)/同じ穴の異なるドリル径(警告)/両面基板で表面配線の端点にピン・スルーホールが
  無い(警告)。

### 統計パネル
- こちらも編集のたびに自動再計算。配線長は直交/45度の区間長を積算した実測値(はんだ付けに
  必要な線材の長さの見積もり)。
- BOM は「部品+値」が同じ配置をグループ化し、refDes をまとめて表示する(例: `R1, R2`)。
  CSV エクスポートは Excel での文字化け対策に UTF-8 BOM 付き。

### ライブラリ・部品・基板データの性質
- ライブラリには3種類の状態がある: **常設で編集不可+再配布不可**(マイライブラリ = 自分の
  作業場所そのもの)、**取込済みで編集不可**(他人の .blib をインストールしたもの、PasS 互換
  ライブラリもこれに準ずる特別な1つ)、**複製由来で編集可**(上記いずれかを複製したもの)。
  この3状態の違いが UI 上で(グレーアウト・施錠アイコン・ボタンの有効無効という形で)
  区別されているが、初見でこの構造自体を理解するのは難しいかもしれない。
- 部品・基板のクロマキー(背景透過色)は、ユーザーが画像を開いた瞬間にその画像の左上ピクセルの
  色を自動的に初期値として採用する(決め打ちの色ではない)。スポイトツールで拾い直せる。
- 基板の背景画像を添付すると、**基板サイズはその画像のピクセルサイズに自動的に従う**
  (格子パラメータの列数・行数・ピッチ・原点から手計算する方式との二者択一で、画像がある方が
  優先される)。裏面画像は「基板を裏から見た向き」で用意する規約(表面画像をそのまま裏返した
  ものではない、PasS のデータ形式を踏襲した規約)。

## 4. 一貫させたい視覚言語(現状の実装から)

- **配線の色**: 表面=青系、裏面=オレンジ系。これは配線ツールのボタン・実際の配線描画・
  ネットハイライトのすべてで統一されている、変えると全体の理解が崩れる基礎的な色分け。
- **基板色の既定値**: FR-4グリーン(`#2F6B4F`)。ただしこれは**基板ごとに変更可能なデータ**であり、
  アプリ全体の配色トークンではない(基板エディタで基板単位に色を変えられる)。
- **重要度の色分け**: DRC のエラー=赤系、警告=黄系。これは一般的な慣習に沿っているので
  そのまま踏襲して問題ない。
- **読み込み専用であることの視覚的表現**: 現状はグレーアウトのみ。ロック的なアイコンなど、
  もう少し積極的な表現があっても良い。
